Вопросы и ответы по Жизненному циклу и тестированию ПО

1. Определите понятие жизненного цикла программного продукта

Жизненный цикл программного продукта (ЖЦ ПС) — это совокупность последовательных этапов, через которые проходит программное обеспечение от момента его возникновения (идеи) до вывода из эксплуатации. Включает стадии планирования, анализа требований, проектирования, разработки, тестирования, внедрения, эксплуатации и сопровождения, а также утилизации. Целью ЖЦ является управление всеми этапами разработки и эксплуатации ПО для обеспечения его качества, эффективности и соответствия требованиям заказчика.

2. Опишите модели жизненного цикла разработки программного продукта

Модели ЖЦ — это структурированные подходы к организации процессов разработки ПО. Основные модели включают:

  • Каскадная (водопадная) модель: последовательное выполнение этапов — требования, дизайн, реализация, тестирование, внедрение, сопровождение. Каждая стадия завершается перед началом следующей.
  • Спиральная модель: итеративный подход, сочетающий элементы прототипирования и управления рисками. Каждая спираль включает планирование, анализ рисков, проектирование, реализацию и оценку.
  • RAD-модель (Rapid Application Development): быстрая разработка с акцентом на создание прототипов и быструю обратную связь с заказчиком, что позволяет быстро адаптировать продукт.
  • V-модель: расширение каскадной модели, где стадии разработки связаны с этапами тестирования (например, этап проектирования соответствует тестированию).
  • Итерационная модель: разработка по циклам, позволяющая постепенно улучшать продукт, добавляя новые функции.

3. Назовите общие принципы моделирования жизненного цикла программных средств. Укажите свойства и особенности различных моделей ЖЦ ПС. Классическая водопадная модель. Спиральная модель ЖЦ ПС. Другие модели ЖЦ ПС. Модель быстрой разработки приложений (RAD-модель)

Общие принципы:

  • Постепенность и поэтапность: разработка разбита на логические стадии.
  • Взаимосвязь этапов: результаты одних этапов служат входными для следующих.
  • Возможность обратной связи и корректировки.
  • Документирование каждого этапа для обеспечения прозрачности и контроля.

Особенности моделей:

  • Водопадная: простая, линейная, подходит для проектов с четко определенными требованиями; риск — невозможность изменений на поздних стадиях.
  • Спиральная: гибкая, позволяет управлять рисками, подходит для сложных и крупных систем.
  • RAD: ориентирована на скорость, подходит для проектов с быстрым изменением требований.
  • Другие модели: например, V-модель, спиральная, итерационная и др.

4. Укажите основные принципы тестирования и отладки ПО. Назовите цели и задачи тестирования, основные этапы. Тестовый цикл.

Основные принципы тестирования:

  • Планирование тестирования.
  • Разделение тестов на уровни и виды.
  • Вовлечение всех участников процесса.
  • Автоматизация повторяющихся задач.
  • Постоянное совершенствование тестовых сценариев.

Цели тестирования:

  • Обнаружение ошибок и дефектов.
  • Проверка соответствия системы требованиям.
  • Повышение надежности и качества ПО.
  • Подготовка продукта к эксплуатации.

Задачи тестирования:

  • Разработка тестовых сценариев.
  • Выполнение тестов.
  • Анализ и документирование ошибок.
  • Повторное тестирование после исправлений.

Основные этапы тестового цикла:

  1. Подготовка тестовой документации.
  2. Планирование тестирования.
  3. Разработка тестовых сценариев.
  4. Выполнение тестирования.
  5. Анализ результатов.
  6. Исправление ошибок.
  7. Повторное тестирование.

5. Определите критерии тестирования

Критерии тестирования — условия, при которых тест считается завершенным. Они могут быть:

  • Покрытие требований: все требования протестированы.
  • Достижение метрик качества: например, процент успешных тестов.
  • Отсутствие критических ошибок.
  • Исполнение всех сценариев.
  • Исполнение плановых сроков.

6. Укажите параметры тестирования

Параметры тестирования включают:

  • Объем тестирования: какие части системы и функциональности покрыты.
  • Типы тестов: модульные, интеграционные, системные, регрессионные и др.
  • Интенсивность: сколько и как часто выполняются тесты.
  • Средства автоматизации.
  • Среды и конфигурации: на каких платформах проводится тестирование.

7. Опишите виды тестирования

  • Модульное: проверка отдельных компонентов или модулей.
  • Интеграционное: проверка взаимодействия межмодулевых связей.
  • Системное: тестирование всей системы как единого целого.
  • Приемочное: проверка соответствия требованиям заказчика.
  • Регрессионное: проверка после изменений, чтобы не нарушить работоспособность.
  • Нагрузочное: оценка производительности под нагрузкой.
  • Тестирование безопасности: выявление уязвимостей.
  • Тестирование интерфейсов: проверка взаимодействия системных компонентов через интерфейсы.

8. Определите основные стратегии восходящего и нисходящего тестирования

Восходящее тестирование: начинается с проверки отдельных модулей, затем постепенно объединяет их в систему (bottom-up). Включает тестирование модулей, интеграции и системы.

Нисходящее тестирование: начинается с проверки системы целиком, затем изолируют компоненты (top-down). Используются заглушки для недоступных компонентов.

9. Определите задачи тестирования методом «Черного ящика»

Тестирование «Черного ящика» сосредоточено на проверке функциональности без знания внутренней реализации. Задачи:

  • Проверка соответствия входных данных ожиданиям.
  • Обнаружение ошибок в логике работы.
  • Валидация требований и спецификаций.
  • Определение корректности обработки ошибок.

10. Опишите стратегию тестирования методом «Белого ящика»

Тестирование «Белого ящика» основывается на знании внутренней структуры программы. Задачи:

  • Проверка логики алгоритмов.
  • Тестирование путей выполнения (тестирование маршрутов).
  • Проверка условий, циклов и ветвлений.
  • Обнаружение ошибок в реализации кода.

11. Укажите способы тестирования модуля

  • Тестирование вручную — запуск сценариев вручную.
  • Автоматизированное тестирование — использование тестовых скриптов и инструментов.
  • Динамическое тестирование — запуск модуля в рабочем режиме.
  • Статическое тестирование — анализ кода без его выполнения (ревью, статический анализ).

12. Определите классификацию ошибочных ситуаций при функциональном тестировании

Ошибки классифицируются по:

  • Виду (логические, синтаксические, интерфейсные).
  • Причинам возникновения (ошибки проектирования, реализации, данных).
  • Влиянию на систему (критические, незначительные).
  • Области системы (модульные, интеграционные, системные).

13. Опишите план модульного тестирования

План включает:

  • Объекты тестирования (модули, компоненты).
  • Методы тестирования (черный/белый ящик).
  • Тестовые сценарии и кейсы.
  • Средства автоматизации.
  • Критерии завершения.
  • Расписание и ресурсы.
  • Методы локализации ошибок.

14. Укажите способы локализации ошибочной области

Используются:

  • Анализ логов и отчетов о ошибках.
  • Использование отладчика.
  • Тестирование по трассировке путей выполнения.
  • Построение диаграмм и графов маршрутов.
  • Метод «деления пополам» (бинарный поиск ошибок).

15. Опишите метод структурного тестирования

Метод основан на анализе внутренней структуры программы, включает:

  • Тестирование путей (тестирование маршрутов).
  • Покрытие операторов, ветвлений, условий.
  • Анализ графа управляющих потоков.
  • Обнаружение ошибок, связанных с логикой исполнения.

16. Опишите структурное тестирование маршрутов

Это тестирование, при котором проверяются все возможные маршруты выполнения программы, чтобы обеспечить покрытие всех ветвлений и условий. Используется граф управляющих потоков (например, граф Вейса).

17. Опишите типы и причины ошибок, обнаруженных при структурном тестировании в вершинах ветвей графа

Типы ошибок:

  • Логические ошибки в условиях.
  • Ошибки в ветвлениях (например, неправильные условия).
  • Ошибки в управлении потоками (например, пропуски ветвлений).

Причины:

  • Неправильная реализация алгоритмов.
  • Недостаточная проверка условий.
  • Ошибки в проектировании логики.

18. Опишите результаты модульного тестирования

Результаты включают:

  • Список обнаруженных и исправленных ошибок.
  • Статистические показатели (процент пройденных тестов).
  • Отчеты о покрытии кода.
  • Выводы о готовности модуля к следующему этапу.

19. Определите нагрузочное тестирование и его назначение. Назовите этапы проведения нагрузочного тестирования

Нагрузочное тестирование — это проверка системы под максимальной или приближенной к ней нагрузкой с целью оценки производительности и устойчивости.

Этапы:

  1. Планирование сценариев нагрузки.
  2. Настройка тестовой среды.
  3. Выполнение тестов.
  4. Анализ результатов.
  5. Определение лимитов и узких мест.

20. Укажите виды функционального тестирования

  • Тестирование функциональности (проверка соответствия требованиям).
  • Тестирование совместимости.
  • Тестирование удобства использования.
  • Тестирование безопасности.
  • Тестирование локализации и интернационализации.

21. Определите испытание информационной системы на этапах подготовки к эксплуатации

Это комплекс мероприятий, включающий:

  • Проверку работоспособности.
  • Проверку на соответствие требованиям.
  • Оценку надежности и безопасности.
  • Подготовку документации.
  • Обучение пользователей.

22. Укажите цели интеграционного тестирования

— Проверка взаимодействия модулей.

— Обнаружение ошибок в обмене данными.

— Удостоверение, что компоненты работают совместно согласно спецификациям.

— Подготовка системы к системному тестированию.

23. Определите назначение тестирования производительности, тестирование сборки

Тестирование производительности: оценка скорости, отклика, пропускной способности системы.

Тестирование сборки: проверка корректности процесса объединения компонентов, сборочного процесса, целостности сборочного образа.

24. Определите жизненный цикл дефекта. Тестовый отчет дефектов

Жизненный цикл дефекта:

  • Обнаружение.
  • Регистрация.
  • Анализ.
  • Исправление.
  • Верификация исправления.
  • Закрытие.

Тестовый отчет содержит описание дефекта, шаги воспроизведения, приоритет, статус, комментарии.

25. Опишите назначение тестирования интерфейсов

Обеспечить корректную работу взаимодействия между системами, модулями или компонентами через интерфейсы. Проверка совместимости, передачи данных, обработки ошибок.

— В ООП: тестирование взаимодействия объектов, методов, наследования, интерфейсов.

— В процедурном: тестирование вызова функций, процедур, модулей, их взаимодействия.

29. Опишите задачи системного тестирования

— Проверка всей системы в реальных условиях.

— Выяснение соответствия требованиям.

— Проверка производительности.

— Оценка надежности и безопасности.

30. Укажите принципы регрессионного тестирования

  • Повторное выполнение тестов после изменений.
  • Автоматизация для ускорения.
  • Покрытие критичных сценариев.
  • Регулярное обновление тестовых сценариев.

31. Опишите издержки тестирования. Методы автоматизации тестирования

Издержки:

  • Время и ресурсы на подготовку и выполнение тестов.
  • Стоимость автоматических инструментов.
  • Обучение персонала.

Методы автоматизации:

  • Использование автоматических средств.
  • Скрипты тестирования.
  • Постоянное интегрирование и автоматизация процессов.

32. Опишите требования к документации тестирования

  • Полнота и точность описания сценариев.
  • Регулярное обновление.
  • Доступность для участников.
  • Включение отчетов, протоколов, дефектных отчетов.

33. Укажите цели и задачи регрессионного тестирования. Виды регрессионного тестирования

Цели:

  • Обнаружение ошибок, вызванных изменениями.
  • Гарантировать, что новые изменения не нарушили существующую функциональность.

Задачи:

  • Повторное выполнение критичных сценариев.
  • Обновление тестовых сценариев.

Виды:

  • Полное регрессионное тестирование.
  • Частичное (выборочное).
  • Автоматизированное регрессионное тестирование.

— Покрытие требований.

35. Определите преимущества и недостатки автоматизации тестирования

Преимущества:

  • Быстрота выполнения.
  • Повторяемость.
  • Повышение охвата тестирования.
  • Возможность раннего выявления ошибок.

Недостатки:

  • Высокие начальные затраты.
  • Требуются навыки.
  • Не все сценарии подходят для автоматизации.
  • Поддержка автоматических тестов требует времени.
